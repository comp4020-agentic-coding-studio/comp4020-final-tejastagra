Look at every screen of Rubble the way a player would, check it against the QA checklist, and fix what fails. Do this before declaring any screen work finished (CLAUDE.md).

1. **Make a clean test app.** Never use the dev server or `data-dev/`. Start a throwaway server on a free port with a temporary data folder, and delete the folder when you are done:
   `scripts/visual-qa.sh` does this and runs the screenshot script for you. Do not start a second `pnpm dev`.
2. **Take the screenshots.** `bash scripts/visual-qa.sh` writes one PNG per screen and state at each viewport (390 x 844 phone, 1366 x 768 laptop and 320 x 568 narrow phone) into `reports/visual-qa/` (not tracked by git), named `<state>--<viewport>.png`, and prints the list. The states are in `scripts/visual-qa.ts`, one entry each: home, every popup (nickname, join with a code, sign up, sign in, forgot password, change password, leave game, shield help, earthquake help), the computer game, the friend waiting screen, a friend game in play, the watching screen, every end popup (win, lose, draw, forfeit, abandoned) and every rematch state (waiting for the other, the other wants a rematch, the other left), quick match waiting and the computer offer, the leaderboard empty and filled, the account page as a guest and signed in, the forced password change, the tutorial (every step) and the style of an error. If a state you expect is missing from the list, the script is wrong: fix the script, not the list.
3. **Look at every screenshot yourself.** Open each PNG with the Read tool and look at it. Do not skim and do not rely on the measurements alone: a measurement cannot see a cramped header, text that is cut off, a box that is too wide for its words or a page that looks plain.
4. **Check each one against `docs/design/qa-checklist.md`** (Q1 to Q14) and the rest of `docs/design/`: no layout shift, no wrapped button label, boxes that fit their content, 16px and 32px spacing, headings on their content's left edge, one centred column, prefilled edit forms, only sensible controls, a way to leave, an empty state that explains itself a header with the Rubble title and a subtitle in the toy style, a header bar with Home at the top of every screen but home (Q12), the board or main card centred (Q13) and each player's colour and marker the same on every screen of one game (Q14). Also look for anything cut off, overlapping, too small to tap, hard to read or inconsistent with the other screens.
5. **Write down what failed** (screen, viewport, which Q or what you saw), then **fix it in the right order**: change the rule or the design file first if the rule is wrong, then the test, then the code (CLAUDE.md "Order of truth"). Add a check to `e2e/layout.spec.ts` for anything a measurement can catch, so it cannot come back.
6. **Run it again** until every screenshot passes. Report the list of screens you looked at and anything you could not fix.

Run the design-reviewer and phone-tester subagents on a screen change as well: they read the diff and measure, and this command looks at the result.
